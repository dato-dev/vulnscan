# Корпус для регрессии на ложные срабатывания

Заблокированный легитимный документ дороже пропущенного тестового образца,
поэтому главная метрика здесь — не полнота детекта, а **ложные срабатывания**.

## Что внутри

`manifest.csv` — разметка (в репозитории). `pdfs/` — сами файлы, скачиваются по
требованию и в репозиторий не попадают.

Источник: датасет
[Cyber-security-final-project/Generated_Injected_PDFs_HARMLESS](https://huggingface.co/datasets/Cyber-security-final-project/Generated_Injected_PDFs_HARMLESS)
на Hugging Face — 1100 файлов, 900 с инъекциями двенадцати типов и 200 без.
Инъекции безвредны: это тестовые образцы вроде EICAR, а не рабочий код.

## Использование

```bash
make corpus         # скачать выборку (по умолчанию бюджет 150 МБ)
make corpus-check   # прогнать и проверить регрессию
```

Выборка воспроизводима: фиксированное зерно, отбор по манифесту.

## Как читать результат

Проверка падает не по проценту, а по **новым** срабатываниям на чистых файлах.
Причина: метка `none` в датасете означает «мы ничего не внедряли», а не
«проверено и безобидно» — исходники брались из реальных корпусов, и часть из них
законно содержит активные элементы.

Разобранные вручную случаи перечислены в `expected.json` с объяснением. Если
проверка падает, у нового файла два пути: либо это настоящее ложное
срабатывание и надо чинить код, либо разбор показал верное срабатывание — и файл
заносится в `expected.json` вместе с причиной.

## Правила YARA

`make corpus-check` гоняет `filetype` и `structure`. Правила проверяются
отдельным шлюзом:

```bash
make rules-check    # компиляция + синтетика + прогон по чистым файлам
```

Он падает на трёх вещах: набор не компилируется, правило перестало ловить свою
синтетику из `samples/generated`, правило сработало на чистом файле, которого
нет в `expected.json`. Разбор такой находки — тот же, что и выше: либо правило
слишком широкое, либо срабатывание верное и файл заносится с объяснением.

Первый же прогон нашёл настоящее ложное срабатывание: `pdf_js_with_autoexec`
искал `/JS` и `/AA` с `nocase`, и в двенадцатимегабайтном договоре они
находились в сжатом потоке как `/js` и `/aA`. Имена объектов PDF
регистрозависимы — `nocase` не ловил ничего, чего не поймал бы без него, зато
утраивал число случайных совпадений.

## Полный конвейер

`make corpus-check` гоняет только локальные стадии: `filetype` и `structure`.
Антивирус и YARA в него не входят, поэтому полнота детекта здесь занижена —
полезная нагрузка в корпусе как раз сигнатурная.

Прогон через весь конвейер:

```bash
python corpus/check.py --api http://ХОСТ:8080
```

На Apple Silicon это бесполезно: у образа ClamAV нет сборки под arm64, а под
эмуляцией демон падает с segfault на потоке реальных документов. Полный замер
делается на x86-хосте.
