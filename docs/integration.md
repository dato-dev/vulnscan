# Подключение к сервису проверки вложений

Документ для команды, которая хочет проверять свои файлы нашим сервисом.

Сервис принимает файл, разбирает его как заведомо враждебный, пересобирает в
безопасную копию и возвращает вердикт с разложением по признакам. Решение, что
делать с вердиктом, принимаете вы: **сервис детектит, политику применяет клиент.**

---

## 1. Получить ключ

Ключ выпускает администратор сервиса:

```bash
curl -X POST https://scan.example.com/v1/admin/keys \
  -H "Content-Type: application/json" \
  -d '{"tenant":"ваша-команда","key_id":"ваша-команда-1","callback_hosts":["hooks.ваш-домен"]}'
```

В ответ придёт секрет. **Он показывается один раз** — сервис хранит его, но
повторно не отдаёт. Потеряли — выпускайте новый и отзывайте старый.

`callback_hosts` — куда вам разрешено слать результат. Пустой список означает,
что коллбэки вам запрещены: адрес приходит из запроса, и разрешать по умолчанию
нельзя. Понадобится другой адрес — попросите добавить, это делается без
перезапуска сервиса.

## 2. Подключиться

Библиотека берёт на себя подпись, повторы и разбор вердикта:

```python
from vulnscan_client import VulnscanClient

async with VulnscanClient(
    base_url="https://scan.example.com",
    key_id="ваша-команда-1",
    secret=SECRET,          # из окружения, не из кода
) as client:
    outcome = await client.scan(content, filename="скан.pdf")
```

Писать своего клиента можно, но подпись придётся повторить точно — см. §6.

## 3. Прочитать вердикт

Это самое важное место, и здесь чаще всего ошибаются.

| Вердикт | Что значит | Что делать |
|---|---|---|
| `clean` | проверен, чист | отдать пересобранную копию |
| `suspicious` | балл между порогами | отдать копию, показать предупреждение |
| `malicious` | заблокирован | файл не отдавать |
| `unsupported` | формат не разбирается | **не считать чистым** |
| `encrypted` | файл под паролем | **не считать чистым** |

```python
if outcome.blocked:
    отказать_пользователю()
elif outcome.safe:
    выдать(await client.download_clean(outcome.scan_id))
else:
    # unsupported, encrypted, незнакомый вердикт
    попросить_другой_файл()
```

**`not blocked` — это не «безопасно».** Файл, который не удалось проверить, не
заблокирован, но и чистым не является. Проверка `if not outcome.blocked` молча
пропустит зашифрованный архив как безобидный — это самая частая ошибка
интеграции, поэтому в библиотеке есть отдельное свойство `safe` с положительным
списком: незнакомый вердикт безопасным не считается.

Ценность сервиса не только в вердикте. Даже для чистого файла лучше отдавать
**пересобранную копию**, а не оригинал: она собрана заново, без активных
элементов, и это работает против того, чего мы ещё не умеем детектить.

## 4. Получить результат: синхронно или коллбэком

Сервис отвечает синхронно, если уложился в `wait_ms` — это примерно 99% файлов.
Не уложился — отдаёт `202`, и результат приходит коллбэком.

```python
if outcome.pending:
    # результат придёт на callback_url либо заберите его сами:
    later = await client.result(outcome.scan_id)
```

**Коллбэк обязан проверяться:**

```python
from vulnscan_client import verify_callback

payload = verify_callback(SECRET, request.body, request.headers)
```

Без проверки ваш эндпоинт принимает вердикт от кого угодно, и «файл чист» может
прислать тот, кто этот файл и подсунул.

Коллбэк подписывается **вашим** ключом. Доставка повторяется 10 раз с растущей
паузой и покрывает около получаса, так что перезапуск вашего приёмника результат
не потеряет. Отвечайте `2xx` при успешном приёме; `5xx` и `429` вызовут повтор,
остальные `4xx` — нет.

Доставка гарантирована **не менее одного раза**: один и тот же результат может
прийти дважды. Делайте обработку идемпотентной по `scan_id`.

## 5. Синхронизируйте часы

Окно подписи — **300 секунд**. При большем расхождении часов между вашей
площадкой и нашей откажет всё, и выглядеть это будет как неверный ключ.

Держите NTP включённым. Если подключение «не работает без причины» — сначала
сверьте время. В нашем логе отказа расхождение видно явно, попросите посмотреть.

## 6. Если пишете своего клиента

Две схемы подписи, потому что задачи разные.

**Запросы с JSON-телом** подписывают тело:

```
timestamp = str(int(time.time()))
signature = "sha256=" + hmac_sha256(secret, f"{timestamp}.".encode() + body).hexdigest()
```

**Загрузка файла** подписывает канонический запрос без тела:

```
POST\n/v1/scan\nваш-key-id
```

Так сделано потому, что подписать тело multipart можно только прочитав его, а
читать тело до аутентификации нельзя — иначе нагрузка уже принята. Целостность
файла при этом обеспечивает TLS.

Заголовки:

```
X-Vulnscan-Key:       ваш-key-id
X-Vulnscan-Timestamp: <timestamp>
X-Vulnscan-Signature: sha256=<hex>
```

## 7. Когда сервис недоступен

Решайте заранее, а не в момент аварии: **что делать с файлом, который не удалось
проверить.** Пропускать непроверенное — значит остаться без защиты именно тогда,
когда что-то уже пошло не так.

Наша рекомендация: отказывать пользователю с понятным сообщением и повторять
позже. Библиотека сама повторяет запрос трижды с растущей паузой, повторяя только
то, что осмысленно повторять: `401` и `400` не повторяются — через секунду будет
то же самое.

Проверяйте `/readyz`: сервис объявляет себя неготовым, если базы антивируса
устарели, — вердикт `clean` по сигнатурам недельной давности ничего не значит.

## 8. Ограничения

- Разбираются PDF и изображения. Офисные документы и архивы вернут `unsupported`.
- Размер файла и частота запросов ограничены политикой вашего тенанта.
- Один и тот же файл проверяется один раз: повтор получает тот же `scan_id`.
  Это не ошибка, а дедупликация — но ответ вы получите на каждый запрос.
- Обезвреженная копия живёт сутки, потом удаляется.
- Имя файла мы не храним и не логируем: в потоке сканов документов оно почти
  всегда содержит персональные данные.

## 9. Что мы просим взамен

Логируйте `scan_id` у себя. При разборе жалобы это единственное, по чему мы
сможем найти проверку: содержимого файла у нас через сутки уже нет.
